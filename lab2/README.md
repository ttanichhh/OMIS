# Платформа событий

Реализация четырёх окон из макетов отчёта Башуры А. О. (страницы 8–9) и классов его объектной модели (страницы 6–7).

## Запуск

```bash
python3 main.py
```

На форме входа есть две роли, логин, пароль, вход и регистрация. Для нового аккаунта выберите роль, введите логин и пароль и нажмите «Зарегистрироваться», затем войдите. Роль существующего аккаунта не меняется переключателем формы.

## Интерфейс по макетам

- Вход — участник/организатор, логин, пароль, вход и регистрация.
- Каталог — поиск по названию или месту, фильтры макета, карточки и кнопки «Заинтересован»/«Пойду», выход. Создавать мероприятие может организатор; участнику это действие недоступно.
- Создание — название, категория, дата, время, место, текстовое описание, «Отмена» и «Опубликовать событие». Публикация и отмена возвращают в каталог.
- Детали — сведения о мероприятии, организатор, число участников, «Принять участие», «Заинтересован» и возврат в каталог.

Категории повторяют каждый макет отдельно: в каталоге «Спорт», «Обучение», «Развлечения», «Прогулка»; в форме — «Спорт», «Игры», «Развлечения», «Прогулка». Несогласованность исходного отчёта зафиксирована в «Список ошибок.md».

Дополнительных экранов настройки, администрирования, участников, статистики и уведомлений нет. На карточку не добавлены кнопки карты, календаря, напоминаний, редактирования, приглашений, удаления и отмены участия; формы комментариев также нет.

## Объектная модель

Операции базовой диаграммы, включая `updateEventDetails`, `cancelRegistration`, `getEventStats` и `onViewStatsClick`, сохранены в классах. Отдельные расширения уведомлений, интеграций и комментариев и их инжекторы сохранены по диаграммам. Основное приложение создаёт `MainUi`, без самостоятельно придуманного объединения расширений и новых экранов.

Уведомления не имеют придуманного срока «за сутки», расписания или отправки приглашений по логину. Список запрещённых слов для `CommentValidator` не задан отчётом; произвольные слова не установлены.

Текстовое описание содержит функции, для которых в отчёте не приведены окна и переходы. Они не являются основанием добавлять собственные макеты. Это ограничение перечислено в актуальной сверке.

## Данные и проверки

SQLite, проверка пароля по хешу, независимые сессии и защита POST-форм сохранены как техническая реализация. Существующие аккаунты и мероприятия не сбрасываются. Новая база получает три примера мероприятий с датами из макетов; пользователь регистрирует свой аккаунт отдельно. Число участников вычисляется по реальным записям.

Файлы: `model.py` — сущности и сервисы; `storage.py` — SQLite; `interface.py` — четыре окна и отдельные классы расширений; `main.py` — запуск и обработка HTTP; `style.css` — оформление.

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют четыре окна, переходы, права, сессии, поля, запись, сохранение данных, отсутствие дополнительных маршрутов и сохранность операций диаграмм.
